# 参数解析器使用指南

## 📋 概述

参数解析器（ParamResolver）是测试框架的核心功能之一，支持在测试用例中使用**变量引用**和**函数调用**，解决了数据联动和动态值生成的问题。

---

## 🎯 解决的问题

### 问题1: 数据一致性问题
**场景**: 前面步骤生成的数据（如uid、batch_no），后续步骤需要引用

**传统方式**（❌ 错误）:
```yaml
# 步骤1: 准备DataHub数据（自动生成uid）
- prepare_datahub_data:
    users:
      - customerName: "张三"  # uid自动生成为 "abc123"

# 步骤2: 插入日志记录
- database_insert:
    data:
      uid: "test_uid_001"  # ❌ 写死的uid，与DataHub中的不一致！
```

**新方式**（✅ 正确）:
```yaml
# 步骤1: 准备DataHub数据（自动生成uid）
- prepare_datahub_data:
    users:
      - customerName: "张三"  # uid自动生成并保存到context.uids[0]

# 步骤2: 插入日志记录
- database_insert:
    data:
      uid: "${context.uids[0]}"  # ✅ 引用DataHub中生成的uid
```

### 问题2: 动态值生成问题
**场景**: batch_no、serial_id等字段需要动态生成

**传统方式**（❌ 错误）:
```yaml
- database_insert:
    data:
      batch_no: "20260210001"  # ❌ 写死的批次号
      serial_id: "test_serial_001"  # ❌ 写死的流水号
```

**新方式**（✅ 正确）:
```yaml
- database_insert:
    data:
      batch_no: "${batch_no()}"  # ✅ 自动生成批次号（格式：yyyyMMdd001）
      serial_id: "${serial_id()}"  # ✅ 自动生成流水号
```

## 📖 语法说明

### 1. 变量引用

**语法**: `${context.变量名}`

**示例**:
```yaml
# 引用简单变量
batch_no: "${context.batch_no}"

# 引用数组元素
uid: "${context.uids[0]}"  # 第1个uid
uid: "${context.uids[1]}"  # 第2个uid

# 引用嵌套对象（暂不支持，待实现）
# name: "${context.users[0].name}"
```

### 2. 函数调用

**语法**: `${函数名()}`

**内置函数**:

| 函数名 | 说明 | 返回值示例 |
|--------|------|-----------|
| `uuid()` | 生成UUID（无横杠） | `"a1b2c3d4e5f6..."` |
| `batch_no()` | 生成批次号 | `"20260210001"` |
| `serial_id()` | 生成流水号 | `"serial_20260210163000_a1b2c3d4"` |
| `timestamp()` | 当前时间戳 | `"2026-02-10 16:30:00"` |
| `date()` | 当前日期 | `"2026-02-10"` |
| `time()` | 当前时间 | `"16:30:00"` |

### 3. 字符串拼接

**语法**: 在字符串中混合使用文本和变量/函数

**示例**:
```yaml
# 拼接前缀
serial_id: "TEST_${uuid()}"  # 结果: "TEST_a1b2c3d4..."

# 拼接多个变量
message: "批次${context.batch_no}包含${context.user_count}个用户"
```

## 💡 实战示例

### 示例1: 断点续传测试用例

```yaml
test_intent:
  preconditions:
    # 步骤1: 准备DataHub数据（自动生成uid和batch_no）
    - intent: "准备DataHub数据"
      primitive: prepare_datahub_data
      params:
        source: "postLoan"
        users:
          - customerName: "张三"
          - customerName: "李四"
      # 执行后，context中会保存：
      # - context.batch_no = "20260210001"
      # - context.uids = ["abc123", "def456"]

    # 步骤2: 插入Job状态（引用batch_no）
    - intent: "插入Job状态"
      primitive: database_insert
      params:
        database: "copilot"
        table: "common_job_status"
        data:
          batch_no: "${context.batch_no}"  # ✅ 引用步骤1生成的batch_no
          job_name: "AiScriptUidPullJob"
          business_type: "postLoan"
          status: "FAIL"
          complete_count: 2

    # 步骤3: 插入日志记录（引用uid）
    - intent: "插入日志记录"
      primitive: database_insert
      params:
        database: "copilot"
        table: "ai_script_recommendation_log"
        data:
          - serial_id: "${serial_id()}"  # ✅ 自动生成流水号
            uid: "${context.uids[0]}"  # ✅ 引用第1个用户的uid
            source: "postLoan"
            execute_status: "INIT"
          - serial_id: "${serial_id()}"  # ✅ 自动生成流水号
            uid: "${context.uids[1]}"  # ✅ 引用第2个用户的uid
            source: "postLoan"
            execute_status: "INIT"
```

## 🔧 技术实现

### 1. 上下文保存
原语执行后，通过 `context.set()` 保存数据：

```python
# 在 prepare_datahub_data 原语中
context.set('batch_no', batch_no)
context.set('uids', generated_uids)
```

### 2. 参数解析
执行器在调用原语前，自动解析参数：

```python
# 在 executor.py 中
resolver = ParamResolver(context)
resolved_params = resolver.resolve(parsed.parameters)
primitive.execute(context, **resolved_params)
```

---

## ⚠️ 注意事项

1. **变量必须先定义后使用**: 引用的变量必须在前面的步骤中已经保存到context
2. **数组索引从0开始**: `${context.uids[0]}` 表示第1个元素
3. **函数名区分大小写**: 必须使用小写，如 `${uuid()}` 而不是 `${UUID()}`
4. **字符串中的引号**: YAML中使用双引号包裹包含 `${}` 的字符串

## 📊 对比总结

| 特性 | 传统方式 | 新方式（参数解析器） |
|------|---------|-------------------|
| 数据一致性 | ❌ 手动写死，容易不一致 | ✅ 自动引用，保证一致 |
| 动态值生成 | ❌ 写死固定值 | ✅ 函数自动生成 |
| 可维护性 | ❌ 修改一处需要改多处 | ✅ 修改一处自动同步 |
| 可读性 | ❌ 看不出数据来源 | ✅ 清晰表达数据关系 |
