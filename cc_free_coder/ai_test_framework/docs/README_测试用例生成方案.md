# 测试用例生成方案总结

## 📋 方案概述

**最终确定方案**: 直接基于知识库生成YAML格式测试用例 + MD格式总览文件

**核心理念**: 
- ✅ 单层设计，无中间层
- ✅ 知识库是唯一的真实来源
- ✅ AI直接生成可执行的YAML用例
- ✅ 同时生成业务友好的总览文件

---

## 🎯 方案演进历程

### ❌ 方案1：两层设计（已废弃）

**设计思路**:
```
知识库 → MD格式用例（业务层） → YAML格式用例（执行层）
```

**废弃原因**:
1. MD格式信息密度不足，无法完整生成YAML
2. 即使增强MD格式，仍有10-30%的YAML内容无法生成
3. 维护两层格式的复杂度高于收益
4. 不符合实际使用场景

### ✅ 方案2：单层设计（当前方案）

**设计思路**:
```
知识库 → YAML格式用例 + MD格式总览
```

**优势**:
1. ✅ 知识库信息完整，可直接生成YAML
2. ✅ 无需维护中间层
3. ✅ MD总览文件业务友好，满足评审需求
4. ✅ 符合实际使用场景

- ✅ 常用查询SQL

**Job组件文件** (TKJ_xxx.md):
- ✅ 输入参数规范

- ✅ 输出结果说明

## 📝 生成流程

### 输入

1. **知识库**: 完整的业务和系统知识
2. **测试场景描述**: 简单的文字描述

**示例**:
```
场景1：验证正常批量生成流程，准备2个用户
场景2：验证断点续传，模拟Job处理2个用户后失败，总共4个用户
场景3：验证失败重试，准备2条FAILURE状态的记录
```

### 处理步骤

1. **步骤1**: 分析知识库结构
   - 读取所有相关知识文件
   - 提取关键信息

2. **步骤2**: 提取业务流程和组件
   - 提取业务步骤
   - 提取原语映射
   - 提取测试数据模板
   - 提取断言验证
   - 提取关键知识点

3. **步骤3**: 生成YAML测试用例
   - 生成文件头注释
   - 生成基本信息
   - 生成关联知识
   - 生成前置条件
   - 生成测试步骤
   - 生成预期结果
   - 添加详细注释

4. **步骤4**: 生成MD总览文件
   - 生成业务流程说明
   - 生成测试覆盖策略
   - 生成测试用例清单
   - 生成覆盖率统计
   - 生成执行建议

### 输出

1. **YAML格式测试用例**: `TC_<流程ID>_<序号>_<用例名称>.yaml`
2. **MD格式总览文件**: `<流程ID>_测试用例集总览.md`

## ⚠️ 关键注意事项

### 1. 数据准备顺序
**必须先清理后准备**，否则准备的数据会被清理掉

### 2. 异步等待时间
**所有Job执行的断言都必须使用timeout和poll_interval**

### 3. 字段映射差异
**common_job_status表使用business_type字段，其他表使用source字段**

### 4. JSON字段处理
**必须使用JSON_UNQUOTE函数**

### 5. 批次号生成
**不要手动指定batch_no，让原语自动生成**
