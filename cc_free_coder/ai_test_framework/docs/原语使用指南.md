## 1. 通用原语 (Generic Primitives)

通用原语是高度抽象、跨业务复用的测试能力单元。

### 1.1 Job操作原语

#### `trigger_scheduled_job` - 触发定时任务

**分类**: job

**描述**: 触发公司统一的Job调度平台上的定时任务

**参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| job_name | str | ✅ | Job名称（如AiScriptUidPullJob） |
| external_data | dict | ❌ | 外部参数（传递给Job的参数） |
| sharding_flag | bool | ❌ | 是否分片执行（默认false） |
| sharding_total | int | ❌ | 分片总数（默认0） |

**返回值**:
```python
{
    'status': 'SUCCESS/FAIL',
    'job_id': 'Job执行ID',
    'flow_id': '调度平台流程ID',
    'message': '执行结果说明'
}
```

**用法示例**:

**示例1: 基础用法 - 触发无参数Job**
```yaml
- intent: "触发定时任务"
  primitive: trigger_scheduled_job
  params:
    job_name: "DailyReportJob"
```

**示例2: 传递外部参数**
```yaml
- intent: "触发离线剧本名单拉取Job"
  primitive: trigger_scheduled_job
  params:
    job_name: "AiScriptUidPullJob"
    external_data:
      source: "postLoan"
      batch_no: "20260213001"
```

**示例3: 使用变量引用**
```yaml
- intent: "触发Job并传递上下文中的批次号"
  primitive: trigger_scheduled_job
  params:
    job_name: "AiScriptUidPullJob"
    external_data:
      source: "postLoan"
      batch_no: "${context.batch_no}"  # 引用上下文变量
```

**示例4: 分片执行**
```yaml
- intent: "触发分片Job"
  primitive: trigger_scheduled_job
  params:
    job_name: "BigDataProcessJob"
    external_data:
      date: "2026-02-13"
    sharding_flag: true
    sharding_total: 10
```

**⚠️ 重要说明**:
1. **只负责调度**: 此原语只负责提交Job到调度平台，不等待Job执行完成
2. **状态含义**: 返回SUCCESS只表示"调度成功"，不表示"Job执行成功"
3. **验证执行结果**: 需要使用数据库断言原语验证Job的实际执行结果
4. **异步执行**: Job执行是异步的，通常需要等待30-120秒

**常见模式**:
```yaml
# 模式1: 触发Job + 等待执行完成
- trigger_scheduled_job:
    job_name: "AiScriptUidPullJob"
    external_data:
      source: "postLoan"

- assert_field_equals:
    table: "copilot.common_job_status"
    field: "status"
    where: "job_name='AiScriptUidPullJob' AND business_type='postLoan'"
    expected: "SUCCESS"
    timeout: 120  # 等待120秒
    poll_interval: 5  # 每5秒轮询一次
```

### 1.2 断言原语

#### `assert_equals` - 相等断言

**分类**: assertion

**描述**: 断言两个值相等

**参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| actual | any | ✅ | 实际值（支持${context.xxx}表达式） |
| expected | any | ✅ | 期望值 |

**返回值**:
```python
{
    'status': 'PASS/FAIL',
    'reason': '断言通过/失败原因',
    'details': {
        'actual': '实际值',
        'expected': '期望值'
    }
}
```

**用法示例**:

**示例1: 基础用法 - 断言字符串相等**
```yaml
- assert_equals:
    actual: "SUCCESS"
    expected: "SUCCESS"
```

**示例2: 断言数字相等**
```yaml
- assert_equals:
    actual: 100
    expected: 100
```

**示例3: 引用上下文变量**
```yaml
- assert_equals:
    actual: "${context.batch_no}"
    expected: "20260213001"
```

**示例4: 引用数组元素**
```yaml
- assert_equals:
    actual: "${context.uids[0]}"
    expected: "abc123def456"
```

**⚠️ 注意事项**:
1. **类型敏感**: "100" ≠ 100（字符串不等于数字）
2. **变量必须存在**: 引用的上下文变量必须在前面步骤中已设置
3. **支持任意类型**: 可以比较字符串、数字、布尔值等

#### `assert_business_rule` - 业务规则断言

**分类**: assertion

**描述**: 根据业务规则验证结果

**参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| rule_id | str | ✅ | 业务规则ID（如BR_001） |
| context_data | dict | ❌ | 上下文数据（不传则使用当前上下文） |

**返回值**:
```python
{
    'status': 'PASS/FAIL',
    'reason': '校验通过/失败原因',
    'details': '校验详情'
}
```

**用法示例**:

**示例1: 验证BR_001（剧本生成规则）**
```yaml
- assert_business_rule:
    rule_id: "BR_001"
```

**示例2: 传递自定义上下文数据**
```yaml
- assert_business_rule:
    rule_id: "BR_001"
    context_data:
      ai_script:
        value:
          script_content: "沟通对象：张三\n沟通身份：催收专员\n沟通策略：温和提醒"
```

**⚠️ 注意事项**:
1. **规则需实现**: 使用前需确认rule_id对应的规则已实现
2. **当前支持的规则**: BR_001（剧本生成规则）
3. **扩展方式**: 在`AssertBusinessRulePrimitive`类中添加新的`_validate_brXXX`方法

### 1.3 数据库断言原语

#### `assert_field_equals` - 断言字段值相等

**分类**: assertion

**描述**: 断言数据库字段值等于期望值（支持超时轮询，适用于等待异步Job执行完成）

**参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| table | str | ✅ | 表名（格式：database.table） |
| field | str | ✅ | 字段名（支持SQL表达式） |
| where | str | ✅ | WHERE条件（不含WHERE关键字） |
| expected | any | ✅ | 期望值 |
| timeout | int | ❌ | 超时时间（秒），默认0表示不轮询 |
| poll_interval | int | ❌ | 轮询间隔（秒），默认2秒 |

**返回值**:
```python
{
    'status': 'PASS/FAIL',
    'reason': '断言通过/失败原因',
    'details': {
        'actual': '实际值',
        'expected': '期望值',
        'elapsed_time': '耗时（秒）'
    }
}
```

**用法示例**:

**示例1: 基础用法 - 查询一次**
```yaml
- assert_field_equals:
    table: "copilot.ai_script_recommendation"
    field: "status"
    where: "uid='abc123' AND source='postLoan'"
    expected: "SUCCESS"
```

**示例2: 超时轮询 - 等待Job执行完成**
```yaml
- assert_field_equals:
    table: "copilot.common_job_status"
    field: "status"
    where: "job_name='AiScriptUidPullJob' AND business_type='postLoan'"
    expected: "SUCCESS"
    timeout: 120  # 最多等待120秒
    poll_interval: 5  # 每5秒查询一次
```

**示例3: 使用SQL表达式提取JSON字段**
```yaml
- assert_field_equals:
    table: "copilot.ai_script_recommendation"
    field: "JSON_UNQUOTE(JSON_EXTRACT(ai_script, '$.value.script_content'))"
    where: "uid='abc123' AND source='postLoan'"
    expected: "沟通对象：张三"
```

**示例4: 引用上下文变量**
```yaml
- assert_field_equals:
    table: "copilot.ai_script_recommendation"
    field: "status"
    where: "uid='${context.uids[0]}' AND source='postLoan'"
    expected: "SUCCESS"
    timeout: 120
```

**示例5: 使用ORDER BY和LIMIT**
```yaml
- assert_field_equals:
    table: "copilot.ai_script_recommendation_log"
    field: "status"
    where: "source='postLoan' ORDER BY create_time DESC LIMIT 1"
    expected: "SUCCESS"
```

**⚠️ 重要说明**:
1. **异步等待**: 设置timeout参数可等待异步Job执行完成
2. **JSON字段处理**: 使用`JSON_UNQUOTE(JSON_EXTRACT(...))`提取JSON字段值
3. **WHERE条件**: 不要包含WHERE关键字，直接写条件
4. **轮询机制**: 在timeout时间内每隔poll_interval秒查询一次，直到匹配或超时

**常见错误**:
```yaml
# ❌ 错误：包含WHERE关键字
where: "WHERE uid='abc123'"

# ✅ 正确：不包含WHERE关键字
where: "uid='abc123'"

# ❌ 错误：JSON字段未使用JSON_UNQUOTE
field: "JSON_EXTRACT(ai_script, '$.value.script_content')"  # 返回带引号的字符串

# ✅ 正确：使用JSON_UNQUOTE
field: "JSON_UNQUOTE(JSON_EXTRACT(ai_script, '$.value.script_content'))"
```

#### `assert_record_count` - 断言记录数

**分类**: assertion

**描述**: 断言记录数等于期望值（支持超时轮询）

**参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| table | str | ✅ | 表名（格式：database.table） |
| where | str | ✅ | WHERE条件（不含WHERE关键字） |
| expected | int | ✅ | 期望记录数 |
| timeout | int | ❌ | 超时时间（秒），默认0表示不轮询 |
| poll_interval | int | ❌ | 轮询间隔（秒），默认2秒 |

**返回值**:
```python
{
    'status': 'PASS/FAIL',
    'reason': '断言通过/失败原因',
    'details': {
        'actual': '实际记录数',
        'expected': '期望记录数'
    }
}
```

**用法示例**:

**示例1: 基础用法 - 断言记录数为1**
```yaml
- assert_record_count:
    table: "copilot.ai_script_recommendation"
    where: "uid='abc123' AND source='postLoan'"
    expected: 1
```

**示例2: 断言记录数为0（验证数据已清理）**
```yaml
- assert_record_count:
    table: "copilot.ai_script_recommendation"
    where: "source='postLoan'"
    expected: 0
```

**示例3: 超时轮询 - 等待数据插入**
```yaml
- assert_record_count:
    table: "copilot.ai_script_recommendation"
    where: "source='postLoan'"
    expected: 2
    timeout: 120
    poll_interval: 5
```

**示例4: 引用上下文变量**
```yaml
- assert_record_count:
    table: "copilot.ai_script_recommendation"
    where: "source='postLoan' AND uid IN ('${context.uids[0]}', '${context.uids[1]}')"
    expected: 2
```

### 1.4 数据库操作原语

#### `database_insert` - 数据库插入

**分类**: database

**描述**: 向数据库表插入数据（支持单条或多条记录）

**参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| database | str | ✅ | 数据库名称 |
| table | str | ✅ | 表名 |
| data | dict/list | ✅ | 要插入的数据（单条用dict，多条用list） |

**返回值**:
```python
{
    'status': 'SUCCESS/FAIL',
    'inserted_count': '插入的记录数',
    'message': '执行结果说明'
}
```

**用法示例**:

**示例1: 插入单条记录**
```yaml
- database_insert:
    database: "copilot"
    table: "common_job_status"
    data:
      job_name: "AiScriptUidPullJob"
      business_type: "postLoan"
      status: "FAIL"
      complete_count: 2
```

**示例2: 插入多条记录**
```yaml
- database_insert:
    database: "copilot"
    table: "ai_script_recommendation"
    data:
      - uid: "abc123"
        source: "postLoan"
        status: "INIT"
      - uid: "def456"
        source: "postLoan"
        status: "INIT"
```

**示例3: 使用函数生成动态值**
```yaml
- database_insert:
    database: "copilot"
    table: "ai_script_recommendation_log"
    data:
      uid: "${uuid()}"
      source: "postLoan"
      batch_no: "${batch_no()}"
      create_time: "${timestamp()}"
```

**示例4: 引用上下文变量**
```yaml
- database_insert:
    database: "copilot"
    table: "ai_script_recommendation_log"
    data:
      uid: "${context.uids[0]}"
      source: "postLoan"
      batch_no: "${context.batch_no}"
```

**⚠️ 注意事项**:
1. **字段必须存在**: data中的字段必须在表中存在
2. **类型匹配**: 字段值类型必须与表结构匹配
3. **主键冲突**: 如果主键冲突会报错，需要先清理数据

## 2. 业务原语 (Business Primitives)

业务原语是针对特定业务场景封装的测试能力单元，不追求通用性。

### 2.1 DataHub业务原语

#### `create_overdue_user` - 创建逾期用户

**分类**: business

**描述**: 创建一个有逾期案件的用户（用于测试剧本生成等业务场景）

**参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| overdue_days | int | ✅ | 逾期天数 |
| user_id | str | ❌ | 用户ID（不传则自动生成） |
| loan_history | int | ❌ | 历史借款次数（默认1） |
| repay_history | int | ❌ | 历史还款次数（默认0） |

**返回值**:
```python
{
    'user': {
        'user_id': '用户ID',
        'name': '姓名',
        'phone': '手机号',
        'age': '年龄',
        'gender': '性别',
        'education': '学历',
        'occupation': '职业',
        'create_time': '创建时间',
        'overdue_days': '逾期天数',
        'loan_history': '历史借款次数',
        'repay_history': '历史还款次数'
    },
    'case': {
        'case_id': '案件ID',
        'user_id': '用户ID',
        'case_type': '案件类型',
        'overdue_days': '逾期天数',
        'overdue_amount': '逾期金额',
        'status': '状态',
        'create_time': '创建时间'
    }
}
```

**用法示例**:

**示例1: 创建逾期15天的用户**
```yaml
- create_overdue_user:
    overdue_days: 15
```

**示例2: 创建有还款记录的逾期用户**
```yaml
- create_overdue_user:
    overdue_days: 30
    loan_history: 3
    repay_history: 2
```

**示例3: 指定用户ID**
```yaml
- create_overdue_user:
    overdue_days: 7
    user_id: "test_user_001"
```

**⚠️ 重要说明**:
1. **自动保存到上下文**: 用户数据保存为`context.current_user`，案件数据保存为`context.current_case`
2. **配合其他原语使用**: 通常与`prepare_dp_data`配合使用
3. **随机生成数据**: 姓名、手机号、年龄等字段会随机生成

**上下文变量**:
执行后会自动保存以下变量到上下文：
- `context.current_user` - 用户对象
- `context.current_user.user_id` - 用户ID
- `context.current_case` - 案件对象

**常见模式**:
```yaml
# 模式1: 创建用户 + 准备DP数据
- create_overdue_user:
    overdue_days: 15

- prepare_dp_data:
    # 自动使用context.current_user.user_id
```

#### `prepare_dp_data` - 准备DP数据

**分类**: business

**描述**: 在DataHub中准备DP产出的数据（批次状态数据）

**参数**:

| 参数名 | 类型 | 必填 | 说明 |

#### `clean_test_data` - 清理测试数据

**分类**: data

## 4. 上下文变量

上下文变量用于在测试步骤之间传递数据。

### 4.1 变量引用语法

**语法**: `${context.变量名}`

**支持的引用方式**:
1. **简单变量**: `${context.batch_no}`
2. **数组元素**: `${context.uids[0]}`、`${context.uids[1]}`
3. **嵌套对象**: `${context.user.name}`（待实现）

### 4.2 常用上下文变量

| 变量名 | 类型 | 说明 | 来源原语 |
|--------|------|------|---------|
| `context.batch_no` | str | 批次号 | prepare_datahub_data |
| `context.uids` | list | 用户UID列表 | prepare_datahub_data |
| `context.uids[0]` | str | 第1个用户的UID | prepare_datahub_data |
| `context.uids[1]` | str | 第2个用户的UID | prepare_datahub_data |

### 4.3 变量引用示例

### 5.4 JSON字段处理模式

**推荐模式**: 使用JSON_UNQUOTE提取JSON字段

# ❌ 错误：直接使用JSON_EXTRACT（返回带引号的字符串）

### 5.6 常见错误避免

#### 错误1: WHERE条件包含WHERE关键字

```yaml
# ❌ 错误
- assert_field_equals:
    where: "WHERE uid='abc123'"

# ✅ 正确
- assert_field_equals:
    where: "uid='abc123'"
```

#### 错误2: 引用不存在的上下文变量

```yaml
# ❌ 错误：batch_no未定义
- assert_field_equals:
    where: "batch_no='${context.batch_no}'"  # 报错：上下文中不存在变量

# ✅ 正确：先准备数据
- prepare_datahub_data:
    source: "postLoan"
    users:
      - customerName: "张三"

- assert_field_equals:
    where: "batch_no='${context.batch_no}'"  # 成功
```

#### 错误3: 数组索引越界

```yaml
# ❌ 错误：只准备了1个用户，但引用第2个
- prepare_datahub_data:
    users:
      - customerName: "张三"

- database_insert:
    data:
      uid: "${context.uids[1]}"  # 报错：索引越界

# ✅ 正确：准备2个用户
- prepare_datahub_data:
    users:
      - customerName: "张三"
      - customerName: "李四"

- database_insert:
    data:
      uid: "${context.uids[1]}"  # 成功
```

#### 错误4: 忘记设置timeout导致断言失败

```yaml
# ❌ 错误：Job是异步的，立即查询会失败
- trigger_scheduled_job:
    job_name: "AiScriptUidPullJob"

- assert_field_equals:
    table: "copilot.common_job_status"
    field: "status"
    where: "job_name='AiScriptUidPullJob'"
    expected: "SUCCESS"  # 失败：Job还未执行完成

# ✅ 正确：设置timeout轮询等待
- trigger_scheduled_job:
    job_name: "AiScriptUidPullJob"

- assert_field_equals:
    table: "copilot.common_job_status"
    field: "status"
    where: "job_name='AiScriptUidPullJob'"
    expected: "SUCCESS"
    timeout: 120  # 等待120秒
    poll_interval: 5  # 每5秒查询一次
```

#### 错误5: 时间函数参数类型错误

```yaml
# ❌ 错误：参数必须是整数，不能是字符串
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      last_login_time: "${timestamp_minus_days('7')}"  # 错误：'7'是字符串

# ✅ 正确：参数必须是整数
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      last_login_time: "${timestamp_minus_days(7)}"  # 正确：7是整数

# ❌ 错误：参数不能是小数
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      last_login_time: "${timestamp_minus_hours(2.5)}"  # 错误：2.5是小数

# ✅ 正确：使用分钟数代替
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      last_login_time: "${timestamp_minus_minutes(150)}"  # 正确：150分钟 = 2.5小时
```

#### 错误6: 时间函数参数为负数

```yaml
# ❌ 错误：minus函数参数不能为负数
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      last_login_time: "${timestamp_minus_days(-7)}"  # 错误：参数为负数

# ✅ 正确：使用plus函数
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      last_login_time: "${timestamp_plus_days(7)}"  # 正确：7天后

# ❌ 错误：plus函数参数不能为负数
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      expire_time: "${timestamp_plus_days(-7)}"  # 错误：参数为负数

# ✅ 正确：使用minus函数
- database_insert:
    database: "copilot"
    table: "user_activity"
    data:
      expire_time: "${timestamp_minus_days(7)}"  # 正确：7天前
```
